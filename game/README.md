# NICASOURCE JAM native project

Open `project.gbsproj` in GB Studio 4.3.2 or select it with the ModRetro plugin.
The distributed `project/` and asset sidecars remain editable. `BASKETBALL` is
a project-local engine scene, registered in `plugins/basketball/engine/engine.json`.

`jam_sim.c` implements portable basketball rules and rating effects in quarter-pixel coordinates. `jam_menu.c` owns selection/backtracking and unique lineup choices. The canonical six-player roster is in `jam_sim.h`.
`basketball.c` maps handheld input, depth-sorts four 16x32 body sprites into
render slots, tracks the ball with the camera, and draws the score/instruction HUD.
The ball has separate ground position and flight height. The seven render slots
use native OAM priority: net first, ball second, depth-sorted bodies after those,
and a human indicator. Visual resources are swapped at scene initialization;
simulation identity is independent of the engine player and actor indices.
The `JAM_FINISH` state animates rim contact, net passage, swish credit, and misses
before the possession reset or loose-ball recovery. Players can keep moving.

From the repository root, run `sh scripts/test.sh` and `sh scripts/build.sh rom`.
Use plugin `web_preview {}` for the official Binjgb browser player. Generated
`build/` files are ignored. See the root README and playtest report for controls,
dependencies, evidence, and limits. The prototype art is deliberately temporary;
approved portrait cells remain unchanged and are placed at 2× size in scouting
cards generated by `scripts/create-scouting-cards.mjs`. Menu tile IDs 192–255 in
both VRAM banks are reserved; palette 7 remains untouched. The game restores its
HUD font when practice starts. Static ball/marker frame bounds stay fixed while
menus are open. The blank project's
original unused resources and native-format license are retained.
