# NS JAM Night Court presentation proof

The approved display name is **NS JAM**. The selected home direction is **A — Night Court**. This milestone proves native-screen quality before producing the complete player intro and updating every card.

The first home/intro proof was rejected visually. Home revision 2 reconstructs the chosen composition with a visible volcano behind city lights, warm sunset, palms, lamps, reflective dark court and foreground ball. **The user approved and locked this home artwork on 2026-11-02.** Preserve its composition, logo and palette while working on the intro. `scripts/night_court_art.py` authors the native pixels; home-specific palettes and tile flips keep the existing intro/card assets independent. See [the approved cartridge capture](../playtests/night-court-v2/home-4x.png) and [validation](../playtests/night-court-v2.md). The intro itself still needs redesign.

Cold boot plays one MATUS shooting sequence, timed over 270 hardware VBlanks. It includes a gather, lift, release, ball arc, swish and landing. A/START (also B) skips to home; the button must be released before confirming another action. Home uses up/down and A/START: Play Game enters existing selection, How to Play shows controls, Replay Intro repeats the proof. B on the first player card returns home; B within rating pages/stages retains existing back behavior. Replay and help return to the selected home item. No idle timer interrupts the user with a repeated intro.

The new MATUS card appears whenever MATUS is highlighted on the main card page, including teammate/opponent stages. The user rejected v3's 48px redraw because it differed from the displayed portrait study. V4 reconstructs the same study as a 96×96 native master, rendered 1:1 with legal tile palettes to preserve its feature positions and expression. The user approved this likeness on 2026-11-02; use it as the reference for MATUS intro artwork. Earlier versions remain intact. Four key ratings retain their own column; all-rating pages, every supplied rating and the other players remain unchanged. See [native v4 captures](../playtests/matus-v4.md).

`jam_front.c` is a pure timer/input state machine; `jam_front_art.c` and generated frame modules own native banked backgrounds. `basketball.c` connects them to existing selection/play. Intro time never advances the match clock: normal lineup initialization resets simulation and the renderer's VBlank reference on match entry.

Animated art uses a common tile set plus two alternating pose regions and a hidden-map VBlank swap. Full-page transitions temporarily map palette colors to navy. Signed BG indices 0–127 in both banks avoid the resident 192–236 font/gauge range and all player OBJ tiles. `jam_front_scene_restore` reloads the court background and palettes before gameplay. Front state reuses menu-tile RAM while menus are inactive; front and Dunk Cam share one palette-save buffer because they cannot overlap.

Initial native attempts exposed a boot crash after adding RAM buffers, partial graphics uploads and a white LCD-off transition. Retained failed/review recordings preserve those observations. The integrated proof reuses RAM, double-buffers animated uploads and uses dark palette staging; the final cartridge was played through boot, menus, ratings and an ordinary made basket.

The planned full intro features MATUS, CHRUX, BAMBI, CHOMPA and MAGIC. MEAT remains playable and is excluded from that cinematic. Production of the other four spotlights, a full soundtrack and the remaining card redesigns follows review of this proof. Uniforms remain temporary.
