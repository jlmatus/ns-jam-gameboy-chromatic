# Repository Guidelines

## Project Scope & Current Phase

**NS JAM** is a native 2-on-2 arcade basketball game for ModRetro Chromatic, targeting Game Boy Color. Read `README.md` for the approved brief and `PLAN.md` for milestones.

Player selection, all six portraits/jerseys, rating effects, CPU levels, arcade dunks/Dunk Cam, and configurable 1/2/4 three-minute periods with repeated one-minute overtime and final results with per-player match stats are implemented; the NS JAM Night Court home and animated MATUS/card proof are integrated for review. Richer quarter intermissions and the other intro/card artwork remain. Continue within the requested milestone; physical cartridge flashing requires a separate request. Saved records remain deferred.

## Project Structure & Module Organization

`game/project.gbsproj` is the editable project; `game/project/` contains native resources and `game/assets/` contains assets. Basketball code lives in `game/plugins/basketball/engine/`; `jam_sim.c` owns ball rules and control handoff; `jam_match.c` owns period timing/transitions and tied-game overtime; `jam_stats.c` credits match box scores and `jam_results.c` owns final-page navigation/tiles; `jam_audio.c` chooses presentation events and `jam_sfx.c` plays native PSG streams; `jam_restart.c` owns inbounds; `jam_dunk.c` owns finishing, and `jam_dunk_cam.c` owns close-up presentation; `jam_contact.c` owns body contact; `jam_look.c` loads player palettes; `jam_front.c` owns the proof home/intro/help flow, generated `jam_front_*` files own background art, `jam_menu.c` owns selection, and `basketball.c` handles rendering/input. `jam_sim.h` holds the canonical roster; `art/roster-physics.json` holds confirmed physical profiles, generated into `jam_bodies.h`; `art/ui/scouting-cards.json` holds approved card copy, generated by `scripts/create-scouting-cards.mjs`; `docs/design/ratings.md` explains effects. `tests/` checks rules; `scripts/` holds build/art tooling; `docs/playtests/` records evidence. Preserve approved `art/portraits/` sources and prompts.

## Build, Test, and Development Commands

- `sh scripts/build.sh rom`: official CLI cartridge build using managed Node 24.
- `sh scripts/test.sh`: compile/run C rules tests with sanitizers.
- `sh scripts/chromatic.sh`: installed plugin MCP session under managed Node.
- Plugin `web_preview {}`: build and serve the official browser player.

Ignore generated `build/` outputs. After an export, run `node scripts/check-native-sprite-budget.mjs`; sprites must stay below UI tile 192. See README for prerequisites and overrides.

## Style & Game Data Conventions

Use four-space C indentation, `snake_case`, and `JAM_` constants. Keep simulation positions in quarter pixels. `jam_turbo.c` owns per-player reserves; preserve them across control handoff and inbounds, and freeze them during pause/Dunk Cam. Use hardware VBlank deltas for match time, not simulation ticks; pause, dead balls/inbounds and Dunk Cam stop the clock. Font/gauge tiles 192–236 stay resident during cinematic transitions. Sound effects use pulse channel 1/noise channel 4 through the stock SFX player; keep event detection independent of simulation/RNG and cut effects on pause. Preserve uppercase names, supplied ratings, and string jerseys, especially `"00"`. Temporary uniforms are placeholders. Front animation uses signed BG tiles 0–127 in both banks with double-buffered poses; reload court art/palettes before play. Front state aliases inactive menu RAM and shares the palette-save buffer with Dunk Cam. No formatter is configured; compile tests with warnings as errors.

## Testing Guidelines

Add meaningful state-transition tests in `tests/jam_sim_test.c` for rules changes. Keep Warm-up forgiving while respecting shooter ratings; human shooting uses unbiased percentage rolls, with no difficulty bonus. Tune opponent pressure separately. Build and play the exact ROM after runtime edits; retain inputs, hashes, and observed frames. Host tests do not verify banking, rendering, or hardware. No coverage threshold exists.

## Commit & Pull Request Guidelines

Use focused imperative subjects, following `Document NS JAM plan and add portrait concepts`. PRs should explain behavior, validation, limitations, and relevant issues; attach genuine gameplay captures for visual changes.
