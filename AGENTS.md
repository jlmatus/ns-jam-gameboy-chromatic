# Repository Guidelines

## Project Scope & Current Phase

**NICASOURCE JAM** is a native 2-on-2 arcade basketball game for ModRetro Chromatic, targeting Game Boy Color. Read `README.md` for the approved brief and `PLAN.md` for milestones.

Player selection, all six portraits/jerseys, rating effects, and CPU levels are implemented; full matches are next. Continue within the requested milestone; physical cartridge flashing requires a separate request. Saved records remain deferred.

## Project Structure & Module Organization

`game/project.gbsproj` is the editable project; `game/project/` contains native resources and `game/assets/` contains assets. Basketball code lives in `game/plugins/basketball/engine/`; `jam_sim.c` owns ball rules, `jam_contact.c` owns body contact, `jam_menu.c` owns selection, and `basketball.c` handles rendering/input. `jam_sim.h` holds the canonical roster; `art/roster-physics.json` holds confirmed physical profiles, generated into `jam_bodies.h`; `art/ui/scouting-cards.json` holds approved card copy, generated by `scripts/create-scouting-cards.mjs`; `docs/design/ratings.md` explains effects. `tests/` checks rules; `scripts/` holds build/art tooling; `docs/playtests/` records evidence. Preserve approved `art/portraits/` sources and prompts.

## ModRetro Chromatic Workflow

Use the **ModRetro Chromatic Plugin** and its applicable skills. Select the intended project before editing. Preserve native IDs, metadata, and assets. The project-local `BASKETBALL` scene extends the stock engine without ejection. Open previews only in Codex's built-in browser.

## Build, Test, and Development Commands

- `sh scripts/build.sh rom`: official CLI cartridge build using managed Node 24.
- `sh scripts/test.sh`: compile/run C rules tests with sanitizers.
- `sh scripts/chromatic.sh`: installed plugin MCP session under managed Node.
- Plugin `web_preview {}`: build and serve the official browser player.

Ignore generated `build/` outputs. After an export, run `node scripts/check-native-sprite-budget.mjs`; sprites must stay below UI tile 192. See README for prerequisites and overrides.

## Style & Game Data Conventions

Use four-space C indentation, `snake_case`, and `JAM_` constants. Keep simulation positions in quarter pixels. Preserve uppercase names, supplied ratings, and string jerseys, especially `"00"`. Temporary uniforms are placeholders. No formatter is configured; compile tests with warnings as errors.

## Testing Guidelines

Add meaningful state-transition tests in `tests/jam_sim_test.c` for rules changes. Preserve generous Warm-up human shooting; tune opponent pressure separately. Build and play the exact ROM after runtime edits; retain inputs, hashes, and observed frames. Host tests do not verify banking, rendering, or hardware. No coverage threshold exists.

## Commit & Pull Request Guidelines

Use focused imperative subjects, following `Document NICASOURCE JAM plan and add portrait concepts`. PRs should explain behavior, validation, limitations, and relevant issues; attach genuine gameplay captures for visual changes.
